# Adrobot

Тестовое задание: приложение для создания кампаний Keitaro и редактирования офферов. Backend — FastAPI + SQLAlchemy 2, миграции — Alembic, frontend — HTML/CSS и JavaScript без сборки. SQLite хранит настройки, черновики и состояние демонстрационного трекера.

## Запуск

Нужен Python 3.12+. Все команды выполняются из корня проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Windows: вместо `source .venv/bin/activate` используйте `.venv\Scripts\activate`.

Интерфейс: http://127.0.0.1:8000. Интерактивная документация: http://127.0.0.1:8000/docs.

По умолчанию включён **демонстрационный режим**: приложение полностью работает без ключа, запросы в Keitaro не отправляются. При первом запуске откройте «Настройки», выберите домен, группу и источник, сохраните. Затем создайте кампанию. Для поиска доступны, например, `Miaflow`, `3749`, `3717`, `11111`.

## Docker (альтернативный запуск)

```bash
cp .env.example .env
docker compose up --build
```

Миграции выполняются при старте контейнера. База хранится в named volume `adrobot-data`, порт опубликован только на localhost. Docker-конфигурация подготовлена, но не запускалась в текущем окружении.

## Подключение Keitaro

В `.env` задайте:

```dotenv
DEMO_MODE=false
KEITARO_URL=https://your-tracker.example
KEITARO_API_KEY=your-key
DATABASE_URL=sqlite:///./adrobot.db
```

`KEITARO_URL` — адрес корня трекера, без `/admin_api/v1`. Перезапустите приложение. В настройках выберите значения из реального трекера. Нужны права чтения доменов, групп, источников и офферов, а также чтения/создания/изменения кампаний и потоков; при незавершённом создании кампания сохраняется выключенной для проверки. Доступность Admin API зависит от редакции Keitaro.

Ключ передаётся только сервером в заголовке `Api-Key`. `.env` и локальные базы исключены из Git. Демо и каждый URL реального трекера имеют отдельное пространство записей в одной базе, поэтому их черновики и настройки не смешиваются.

Интеграция реализована по [официальной спецификации Admin API](https://admin-api.docs.keitaro.io/) и описанию учебного стенда. Адрес API стенда — `https://keitaro-for-tests.etolegko.com/admin_api/v1`; в `.env` укажите только `https://keitaro-for-tests.etolegko.com`. Войдите в админку через GitHub, нажмите «API ключ» вверху и сохраните ключ локально в `.env`.

На стенде доступны домен **1813**, группа **10332 (FORTESTS)** и источник **836 (FORTESTS)**. Выберите их в настройках приложения. Кампании называйте с префиксом `test_фамилия_`, например `test_kazakevic_campaign1`. Ссылка в админке: `https://keitaro-for-tests.etolegko.com/admin/#!/campaign.editor/<id>`.

На стенде нет переходов и статистики, а DELETE удаляет кампании окончательно. Приложение не вызывает DELETE при ошибке создания: незавершённая кампания сохраняется выключенной. Проверка с ключом стенда выполнена 25 ноября 2026 года через HTTP API приложения: создана кампания `test_kazakevic_20261125_210504` (ID 351), проверены оба потока, добавление офферов, закрепление и пересчёт долей, восстановление, отмена и отправка изменений. Итог на стенде: два оффера по 50%. Во время проверки были обрывы сети; результат отправки подтверждён повторным чтением потока. Автотесты отдельно используют имитацию HTTP-ответов.

## Создание кампании

1. Введите название и ISO alpha-2 коды стран через запятую (`AU,MX,RO`). Коды проверяются по справочнику, дубликаты удаляются.
2. Найдите оффер по названию или ID и выберите результат.
3. Нажмите «Создать кампанию».

Создаётся кампания с ротацией потоков по позиции, выбранными доменом, группой и источником. Кампания первоначально выключена. Первый поток принимает указанные страны и выполняет HTTP-редирект на `https://google.com`. Второй поток типа `default` без фильтров направляет остальной трафик на оффер с долей 100%. Сбор кликов включён у обоих потоков. После создания потоков кампания включается.

Если создание потоков или включение кампании завершилось ошибкой, приложение пытается выключить созданную кампанию и показывает её ID. Кампания и её потоки сохраняются для диагностики. Если сеть оборвалась при создании самой кампании, её ID может быть неизвестен: проверьте список в Keitaro перед повтором. Автоматических повторов POST нет, чтобы не создавать дубликаты. Запросы GET повторяются до трёх раз при обрыве соединения или HTTP 502/503/504.

## Редактор

Откройте кампанию и выберите поток с офферами. Потоки прямого редиректа доступны в списке, но не редактируются этим редактором.

- Поиск и добавление оффера по ID/названию. Дубликаты запрещены.
- Удаление выставляет долю 0% и оставляет строку с кнопкой «Восстановить». Последний активный оффер удалить нельзя.
- Доли свободных офферов распределяются поровну. Остаток от деления на целые проценты получают первые офферы по порядку: для трёх — `34/33/33`.
- Ввод процента закрепляет долю. Кнопка «Закреплена» снимает фиксацию. Оставшиеся проценты делятся между свободными офферами: закреплённые `25%` и два свободных → `25/38/37`.
- Сумма закреплённых долей не может превышать 100%. Если закреплены все офферы, сумма должна быть ровно 100%. При 100% закреплённого трафика свободные офферы могут иметь 0%.
- Изменения сохраняются в локальном черновике после каждого действия и переживают обновление страницы и перезапуск сервера. Сам Keitaro до «Push to KT» не меняется.
- «Отменить» восстанавливает исходное состояние черновика. «Загрузить из Keitaro» заменяет его свежими данными; при несохранённых изменениях интерфейс запрашивает подтверждение.
- «Push to KT» заменяет список офферов потока. Лендинги, фильтры и другие параметры не отправляются и не меняются. Неактивные привязки офферов сохраняются.
- Перед отправкой приложение сравнивает исходный снимок потока со свежим ответом Keitaro. При расхождении возвращает 409 и сохраняет черновик. Ревизия черновика также защищает от устаревших изменений из другой вкладки.

Закрепления — локальная помощь при редактировании; после успешной отправки/загрузки сбрасываются. Это не параметр Keitaro.

## Миграции и тесты

```bash
alembic upgrade head
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Точный набор версий, использованный при проверке, сохранён в `requirements.lock`; для его воспроизведения: `python -m pip install -r requirements.lock`.

Тесты используют отдельную временную SQLite-базу и не трогают рабочие данные. Проверяются маршрутизация, настройки, пересчёт долей (от 1 до 100 офферов), закрепление, удаление/восстановление, отмена и отправка, сохранение лендингов и неактивных офферов, конфликты, ошибки HTTP и компенсация неполного создания.

Проверка схемы и откат последней миграции:

```bash
alembic current
alembic downgrade base
alembic upgrade head
```

`downgrade base` удаляет локальные настройки, черновики и демонстрационные кампании. Для новой миграции: `alembic revision --autogenerate -m "description"`, затем проверьте сгенерированный файл и выполните `alembic upgrade head`.

## Структура

```text
app/main.py        HTTP API и операции кампаний/черновиков
app/keitaro.py     HTTP-адаптер Keitaro и локальный симулятор
app/shares.py      алгоритм распределения процентов
app/db.py          SQLAlchemy-модель и хранилище JSON-записей
app/config.py      конфигурация из окружения и .env
app/static/        интерфейс без сборщика и внешних ресурсов
migrations/        миграции Alembic
tests/             сценарии API, адаптера и расчёта долей
```

JSON-записи выбраны для хранения снимков меняющейся схемы Keitaro: трекер остаётся источником кампаний и офферов, отдельная локальная копия его реляционной модели не нужна.

## Границы реализации

Это однопользовательский инструмент для локального запуска: нет собственной авторизации. Запускайте на `127.0.0.1`; для общего доступа нужен защищённый reverse proxy с авторизацией. Используйте один worker: операции сериализованы `asyncio.Lock`, межпроцессная блокировка не реализована. Проверка внешних изменений выполняется перед PUT; Keitaro не предоставляет здесь атомарный compare-and-swap, поэтому одновременное редактирование непосредственно между GET и PUT всё ещё возможно. При сетевом таймауте операции проверьте трекер перед повтором.

Статистика и графики из видео не входят в реализацию: задание требует добавление/удаление офферов и корректные доли. При большом числе офферов поиск можно перенести на серверный поиск Keitaro и добавить кэш справочников; сейчас адаптер получает список и фильтрует его, выводя первые 50 совпадений.
